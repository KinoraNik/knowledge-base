# База знаний отдела поддержки: структура и принципы
## 1. Зачем нужна база знаний
База знаний помогает пользователям решать свои задачи самостоятельно. Это снижает нагрузку на техподдержку и экономит время сотрудников. Хорошая база знаний структурирована и содержит актуальные ответы.
## 2. Принципы организации
Материалы в базе знаний должны соответствовать трем главным принципам:
1. **Краткость.** Никакой «воды», только инструкции по делу.
2. **Актуальность.** Если интерфейс изменился, статья должна быть обновлена в кратчайшие сроки.
3. **Перелинковка.** В каждой статье должны быть ссылки на смежные разделы (например, из FAQ на инструкцию по настройке).
## 3. Структура разделов
Разделы базы знаний организованы по принципу «от общего к частному». Сначала пользователь знакомится с продуктами, затем ищет ответы на конкретные вопросы в FAQ, а если сталкивается с ошибкой — переходит в раздел с инструкциями по решению проблем.

### 3.1 Продукты и сервисы
Раздел содержит обзоры модулей системы «СкладПро» и описание их функций (учет товаров, работа с заказами, аналитика).
### 3.2 Частые вопросы (FAQ)
Вопрос: Как добавить новый товар в систему?
Ответ:

- Войдите в систему под своей учётной записью.

- Перейдите в раздел «Товары» (левое меню).

- Нажмите кнопку «Добавить товар» (в правом верхнем углу).

- Заполните обязательные поля: название, артикул, единица измерения, цена.

- Нажмите «Сохранить».

**Важно**: если товар уже есть в системе, но вы не видите его в списке, проверьте фильтры (возможно, стоит фильтр «Только активные»)

*Совет: чтобы не заполнять карточку каждый раз вручную, используйте импорт из Excel (раздел «Товары» → «Импорт»).*

### Как изменить цену товара?

Если стоимость товара изменилась, зайдите в карточку товара, нажмите «Редактировать» и укажите новую цену в поле «Цена». Сохраните изменения.
### 3.3 Инструции по решению проблем
Если у возникла ошибка, первым делом проверьте раздел [«Решение проблем»](troubleshooting.md). Если вашей проблемы там нет, обратитесь в службу поддержки. При обращении обязательно укажите код ошибки и шаги, которые привели к ее появлению.
## 4. Критерии хорошей статьи
Хорошая статья начинается с четкого заголовка, который отражает суть проблемы. В первом абзаце должно быть краткое описание ситуации. Далее — пошаговая инструкция. В конце статьи полезно добавить блок «Важно» или «Совет», чтобы предупредить пользователя о частых ошибках.
## 5. Как поддерживать актуальность
Ответственный за базу знаний должен регулярно проводить аудит статей. Также важно реагировать на обратную связь от агентов поддержки: если они часто получают один и тот же вопрос, значит, в базе знаний не хватает статьи или она написана непонятно. Все изменения должны вноситься через GitHub (pull request), чтобы у каждой правки была история.
